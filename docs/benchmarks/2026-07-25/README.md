# dUMI v2.0.0 benchmark and profile evidence

This directory is the curated, public evidence package for production-source
freeze
[`299532964a57905c835bd750563988a09af6e1df`](https://github.com/justinblethrow-cloud/dUMI/commit/299532964a57905c835bd750563988a09af6e1df).
The interpretation and claim boundaries are in
[`docs/PERFORMANCE.md`](../../PERFORMANCE.md).

## Benchmark package

[`benchmark/`](benchmark/) contains the path-neutral primary outputs of the
standard seven-repetition comparison:

- `STATUS.json`: terminal runner state;
- `manifest.json`: exact commits, dependencies, runtime identity, JVM options,
  workload definitions, and build-source hashes;
- `environment.json` and `environment.txt`: public host and tool metadata;
- `design.tsv`: the predeclared treatment schedule;
- `measurements.tsv`: every raw and ready measurement;
- `summary.tsv`: per-cell absolute statistics;
- `comparisons.tsv`: matched candidate-versus-upstream ratios;
- `correctness.tsv`: per-cell correctness status;
- `evidence.sha256`: checksums for the eight primary benchmark files;
- `privacy-scan.json`: the runner's public-evidence scan result;
- `inputs/`: generator metadata and input hashes, without the generated
  SAM/BAM files;
- `full-bundle.MANIFEST.sha256`: the inventory of the retained full run before
  curation.

The reportable run was launched from a clean detached checkout. It records
`worktree_was_dirty: false`, seven repetitions, the standard workload profile,
and runtime ID
`04385711a6838b779a934a4d3b0ae9d2a71106e108b465895f284a1fa0aa4566`.

The full bundle's `MANIFEST.sha256` and `evidence.sha256` both verified before
files were copied here. `full-bundle.MANIFEST.sha256` is retained as an
inventory receipt; it will report omitted files if run against this curated
subset. Its SHA-256 is
`20db57ac4fcaa7601b3430a9374cc468e80be54c96736f1a30a43cfcd0a538a4`
and is also anchored by this directory's `SHA256SUMS`. `evidence.sha256` is
directly verifiable here.

Per-run logs, compiled classes, dependency JARs, generated inputs, result BAMs,
warm-ups, source archives, and process temporary directories are omitted from
Git. Relative log references in `measurements.tsv` describe their locations in
the full sealed bundle and are not links within this curated directory.

## Allocation profile

[`profile/`](profile/) contains:

- `allocation-aggregate.json`: a bounded, path-neutral aggregate of three Java
  Flight Recorder allocation samples;
- `profile-correctness.json`: the whitelisted workload and semantic checks for
  all three runs;
- `profile-receipt.json`: frozen source, build, runtime, and curated-file
  hashes.

Raw JFR recordings, output BAMs, and logs are intentionally excluded because
they are large and can contain runtime metadata. Profile elapsed times are not
performance measurements.

## Verification

From this directory:

```bash
(
    cd benchmark
    sha256sum -c evidence.sha256
)
sha256sum -c SHA256SUMS
```

`SHA256SUMS` covers every curated file except itself. Repository
[`.gitattributes`](../../../.gitattributes) enforces LF line endings for the
checksummed text formats.

## Curation boundary

Benchmark result files and input receipts were copied byte-for-byte from the
sealed reportable bundle. The full manifest was renamed to prevent it from
being mistaken for a checksum list of the smaller public subset.

The profile aggregate and correctness summary were generated by the committed
tools. `profile-receipt.json` was created from an allowlist of source hashes,
tool versions, normalized JVM settings, and non-identifying operating-system
fields. No organization names, private paths, usernames, hostnames, raw read
data, or credentials are included.
